# 带引用问答实现与验证

版本：0.10.0；日期：2026-11-20。对应建设计划第 7 项。

## 已实现的回答方式

提供正式知识库的 `ask` 命令和工作台「带引用问答」，支持 BM25／本地语义／混合检索。默认 `extractive` 模式可直接使用，不需要大模型或密钥。

回答由系统组装完整来源摘录及引用，保留章节、步骤、表格和警告；不是任意生成的维修建议。可选 Ollama 模型负责在合格证据中选证或拒答，不能自由改写回答、参数、单位和否定词。模型只能返回 `decision` 与 `evidence_ids`，输出其他字段、重复或不存在的引用均被拒绝。此约束使已发布文字可逐字追溯到证据，不能证明所选资料与问题在语义上完全一致。

本阶段没有开放自由摘要、多轮对话、图像理解或工具调用。若后续增加自由生成，应另做论断级证据与参数校验，不能沿用“引用存在即正确”的判断。

## 范围与证据校验

问答要求显式选择**车型及单一年份**；品牌沿用当前库范围。允许检索未知资料的选项不会让未知适用范围获得作答资格。问题中明确出现的年份与筛选年份不一致时要求重新确认；自然语言中的所有车型、品牌和市场名称并不自动解析，实际范围以结构化筛选为准。

流程如下：

1. 在当前活动且审核通过的资料中按品牌、车型、年份、类型和版本检索，最多读取前 20 个切块候选；不查询历史或待复核材料。
2. 排除仅含标题／图片／图注的候选。使用有限的中文词项覆盖检查正文主题，不能把高语义相似度本身作为答案存在的证明。通俗别称、长问题或复杂推理可能被保守拒答。
3. 常见故障码及带连字符部件号要求完整匹配。支持扭矩、电压、间隙／尺寸、温度、压力和容量的数值型问题；参数须出现在与问题主题对应的同一句或表格行，不能拿同段其他部件的数值补空。
4. 引用扩展到**完整命中章节和明确关联证据**，保留步骤顺序、表格、否定词和警告。章节及阅读顺序关联仍需人工核对，不自动证明相关内容都适用于同一工况。
5. 在全部合格候选及其上下文中检查对应单位的多个参数值。存在不同值时拒绝选择，要求限定资料版本或核对工况；不自动换算单位或判断哪个数值正确。空格和 `N·m/Nm` 等格式差异归一化，不做全套物理量等价推理。
6. 默认最多 4 个章节证据、合计 16000 字符；证据过多或完整表格超限时要求缩小问题，不截断后作答。该字符限制不是对任意服务端模型 token 上限的保证。
7. 本地摘录器或显式配置的模型进行选证。系统只用已核验源文本组装答案，在选证前后复查活动状态、来源运行、元数据修订、适用范围和切块；期间撤下、替换或重处理会阻止旧回答。

数值冲突检查和主题覆盖均是有边界的规则：多工况、混合单位、代词指代、同一长句的多个部件及自然语言矛盾仍需人工核对；本实现不等于通用语义蕴含验证。对多个值采取拒答，会牺牲部分可答率。

## 引用与附件

每条引用含文档 ID、逻辑身份、来源哈希、来源运行、规则摘要、元数据修订、资料版本、适用范围、章节路径、块记录和来源定位。答案携带生成时间、选证提示版本、检索模式及证据摘要。

页码从实际来源位置取得；HTML／JSON／DOCX 没有可靠物理页码时明确“未提供”，不通过标题或段号猜页码。PDF 已有定位和原页核对沿用第 4 项入口。表格原样呈现，校验图片通过已有附件入口查看，不把图片字节送给选证模型，也不声称读取了图片内的信息。

图片资料仍执行原有复核门禁。本次端到端样例中的图片属于待复核文档，**没有为了展示问答而放行**；已通过资料的图片引用展示由契约测试覆盖。真实厂商资料仍保留原有复核状态。

工作台需点击「基于证据回答」才执行问答；普通输入／筛选重跑不会重放旧答案。本次结果可以下载 JSON，不默认落库保存聊天历史。下载文件是生成时的证据快照，不随后续撤下自动撤销，不能当作实时发布状态。

## 结构化结果

| 状态 | 含义 |
| --- | --- |
| `answered` | 输出来源摘录和引用；不是语义正确性保证 |
| `needs_scope` | 缺少车型／单一年份，或问题年份与筛选冲突 |
| `insufficient_evidence` | 缺少足够且适用的正文、参数，或选证器拒答 |
| `conflicting_evidence` | 候选上下文出现多个对应参数值，需进一步核对 |
| `context_limit` | 完整章节过多或超出上下文预算，未截断作答 |
| `invalid_model_output` | 自定义选证器返回无效格式或不存在的引用 |
| `stale_evidence` | 作答期间来源更新、撤下或不可用 |

配置、网络和 Ollama 协议错误明确报错，不输出未校验响应、不自动退回另一模式。CLI 的结构化拒答是已处理结果，退出 0；格式和配置错误退出 2，自动化使用时应检查 JSON 的 `status`。

## 使用方法

默认摘录方式不需要额外大模型：

```bash
.venv/bin/autorepair ask '火花塞安装扭矩是多少' --brand aurora \
  --model sedan --year 2024

# 在已有本地语义模型的环境下选择混合召回
.venv/bin/autorepair ask 'P0300 的检查项目是什么' --brand aurora \
  --model sedan --year 2024 --mode hybrid
```

默认库为 `artifacts/knowledge.sqlite`，可用 `--database PATH` 指定其他库。示例问题只在已有对应适用资料时可回答；不要把仓库自制数值当作真实维修参数。

自制演示资料可在隔离目录加工：

```bash
.venv/bin/autorepair process examples/qa/manual.html --brand aurora \
  --model sedan --year-range 2024 --document-type manual \
  --document-version demo-1 --output work/qa-example
.venv/bin/autorepair ask '火花塞安装扭矩是多少' --brand aurora \
  --model sedan --year 2024 --database work/qa-example/knowledge.sqlite
```

可选 Ollama 选证接口按 [官方 `/api/chat` 文档](https://docs.ollama.com/api/chat) 实现，使用 JSON Schema、非流式响应和温度 0：

```bash
uv sync --extra docling --extra semantic --extra qa
# 自行准备 Ollama 服务及已安装模型；本项目不自动安装或下载大语言模型
.venv/bin/autorepair ask '火花塞安装扭矩是多少' --brand aurora \
  --model sedan --year 2024 --engine ollama \
  --qa-config configs/qa/ollama.example.yaml
```

配置模板仅填写 `endpoint`、`model`，以及可选 `api_key_env`、`timeout_seconds`。模板中的模型名是示例，需与实际已安装模型一致；当前只记录模型名，不验证 Ollama 权重摘要，标签变化会影响选证可复现性。

密钥只从**显式指定名称**的环境变量读取，不放进 YAML、仓库、提示或问答结果。URL 不允许内嵌凭据、查询参数或重定向；本机可用 HTTP，其他服务必须 HTTPS。请求不继承代理环境变量。选择外部服务意味着问题和脱敏后的合格正文会发送到配置目标，使用者须确认服务目标；默认摘录方式不调用任何外部模型。

选证请求不发送图片、原始文件字节或完整库，只发送本问题的合格正文及范围标签；问题执行现有有限联系信息脱敏。该脱敏规则不等于全面敏感信息识别。响应上限 64 KiB，超时、未完整结束、错误格式或服务异常均停止作答，错误消息不回显凭据和原始响应。

## 验证结果

- **225 项测试通过**，新增 47 项问答及接口验收。覆盖精确来源、参数单位、章节上下文、步骤／表格／图片引用、警告保留、品牌与适用范围隔离、未知及待复核排除、参数冲突、版本更新、生成期间撤下／元数据修正／重处理、上下文超限、伪造引用、额外生成文本、配置与密钥、服务错误及界面操作。
- [独立流程结果](qa-results.json)：两个虚构品牌的实际 HTML 解析、规则门禁、正式入库、数值答复、完整步骤／警告／表格、无页码提示、待复核图片排除、无答案拒答、参数冲突与撤下，共 **18 项检查通过**。
- Ollama 原生 HTTP 协议通过本机临时服务端模拟完成端到端测试；其他超时／格式／响应上限等用确定性接口测试验证。**本机未安装 Ollama，没有执行真实大语言模型推理，也没有宣称模型选证准确率。** 默认摘录方式已真实跑通，不依赖模拟模型。
- 另在隔离自制库以真实本地 BGE 模型执行混合召回，再完成来源摘录问答，参数、引用和警告均通过检查；这是嵌入检索联调，不是 LLM 推理测试。
- 浏览器在隔离自制库验证：未选车型年份拒答，填写后展示 `42 Nm` 演示参数、操作步骤、`0.8 mm` 表格及禁止强行拧入警告；HTML 不虚构页码，待复核 `99 Nm` 不进入回答；无答案问题拒答，无页面异常。
- 原有 26 份输入的 437 块／155 章节覆盖审计、3 份真实缓存资料的 16 页／18 表格／24 图片展示审计，以及 14 项生命周期流程检查均通过；没有修改用户实际原件库或放行真实待复核资料。
