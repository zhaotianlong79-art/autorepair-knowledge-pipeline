## 一 开源项目比较与选择依据

选型采用定性比较，依据官方仓库和文档。没有进行相同样本、相同硬件下的性能对测，因此不以星数、主观分数或“准确率更高”作为选择结论。

| 比较维度 | Docling | MarkItDown | Unstructured |
| --- | --- | --- | --- |
| 主要产物 | 统一文档结构，可导出 Markdown 和 JSON [1] | 以 Markdown 转换为主要目标 [4] | 文档分区后的结构化元素 [5] |
| 维修文档适配点 | 版面、阅读顺序、表格与 OCR [1] | 适合快速建立转换入口 [4] | 适合按标题、正文等元素加工 [5] |
| 需要自行补齐 | 品牌元数据、术语、引用、质量门禁 | 领域加工与可追溯结构 | 领域加工与品牌规则 |
| 工程代价判断 | 模型下载与资源控制需要验证 | 可作为降低转换复杂度的备选 | 再引入一套解析体系会增加维护面 |
| 代码许可证 | MIT [2] | MIT [4] | Apache 2.0 [5] |
| 本项目角色 | 第一候选 | 触发条件满足时评估 | 复杂样本效果不足时评估 |

### 为什么优先选 Docling

维修知识通常包含步骤、警告、参数表和章节引用。统一中间结构有利于后续规则定位与来源追踪，Docling 的能力覆盖这一入口需求。这个判断是针对本项目的架构适配性，并非对所有解析工具的效果排名。隐藏 HTML 内容识别、品牌分类和业务元数据不视为底座自动解决。

### 为什么首版不整体接入 Data Juicer

Data-Juicer 支持 YAML 编排、数据清洗和分析 [3]。本项目还需要逐条修改记录、品牌覆盖规则、跨文档引用和部件实体约束。首版采用小型有序规则管道更便于解释和测试；未来批量规模成为瓶颈时，再通过标准 JSONL 接口评估接入。该选择属于工程范围取舍。

### 复用方式与许可证处理

推荐创建自己的业务包，通过适配层调用公开依赖，不直接搬运并改名整个上游仓库。README 明确列出上游能力和自研模块；确需复制代码时保留原版权、许可证及适用声明。模型权重的许可独立核对，不能把 Docling 代码的 MIT 许可推及所有模型 [1][2]。

已有汽车参数提取类仓库仅供功能思路参考。前期未找到明确许可证的仓库，不纳入代码复用清单。依赖确切版本、模型名称和权重版本，在批准后的技术验证阶段确定并锁定。

## 二 系统方案与技术边界

主链路为本地文件接入 → 解析与 DOM 预处理 → 统一文档模型 → 品牌规则加工 → 映射与引用检查 → 质量门禁 → Markdown 与 JSONL 输出 → 检索验证及可视化审阅。原始文件与加工结果分别保存。

| 模块 | 建议技术或实现 | 承担职责 |
| --- | --- | --- |
| 核心语言与配置 | Python 3.12；YAML；Pydantic | 类型校验、规则配置校验与输出契约 |
| 文档解析 | Docling 适配器 | PDF 与 DOCX 解析；保留块结构及可获得的来源定位 |
| HTML 与内嵌 HTML | lxml 或 Beautiful Soup | DOM 遍历、已声明隐藏内容处理、正文及链接提取 |
| 规则执行 | 自研有序算子管道 | 规则 ID、优先级、品牌覆盖、冲突检测、修改审计 |
| 映射与任务记录 | SQLite | 术语、部件、引用、运行记录与结果持久化 |
| 展示与检索 | Streamlit；首版精确匹配加 BM25 | 加工前后对比、问题列表、来源定位及检索对照 |
| 工程质量 | pytest；Ruff；GitHub Actions | 关键业务回归、配置校验及公开样例的持续验证 |

上表为拟用技术清单，尚未安装或验证兼容性。首版不引入 LangChain、向量数据库、任务队列或大型服务编排；预留检索接口后再评估扩展。

### 文档格式的明确范围

PDF 包括数字版及少量扫描样例；Word 首版明确为 DOCX，旧版 DOC 待后续增加转换适配。HTML 首版处理本地静态文件及 JSON 字段内嵌片段。display:none、hidden、aria-hidden 等按可配置策略处理并记录；外部样式表、完整 CSS 计算和 JavaScript 渲染不纳入首版承诺。

### 部署与资源假设

先以本地 CPU 和单任务运行为基线，模型预下载后支持离线运行；底座支持从本地模型目录加载 [6]。不要求 NVIDIA GPU，不调用付费 LLM API。模型缓存位置、下载体积、冷启动、峰值内存和每页耗时均在技术验证时实测，不预先承诺处理吞吐。

### 底座替换条件

若目标环境安装失败、资源不可接受，或代表样本的关键表格持续丢失，则保留统一文档接口，用相同样本评估 MarkItDown 或 Unstructured。只有比较结果支持时才替换或增加适配器，并同步调整决策记录；不静默切换解析器。

### 计划中的九类规则

结构规范、专名规范、文档编号与引用、工具术语、部件术语、技术文风、长尾术语、个人信息处理、检索输出准备。每类首版至少提供一条可执行规则与正反例；覆盖一种机制不等于覆盖该领域所有业务情况。

## 四 关键数据与规则设计

### 统一文档与来源追踪

每份文档保存 doc_id、brand、model、year_range、source_hash、source_path、parser_version、schema_version 和 blocks。每个块保存 block_id、类型、原文、规范文本、章节路径及来源定位。PDF 使用可获得的页码和坐标；HTML 使用 DOM 路径；DOCX 使用段落或表格位置，不能伪造稳定页码。

业务记录保存 component_id、标准名称、原始名称、spec_type、原始数值与单位、文档版本和证据块 ID。品牌、车型、年份或手册版本不明确时保持未知并报告，避免把不同适用范围的同名部件错误合并。

### 规则的可解释执行

每条规则包含 rule_id、version、适用范围、处理字段、匹配条件、动作与严重等级。按固定阶段执行，品牌覆盖同名公共规则必须声明覆盖关系。未知动作、重复 ID、循环引用和同优先级冲突在运行前报错；YAML 仅允许已注册动作，不执行任意代码。

每次命中记录原始值、变更值、文档及块 ID、规则 ID、规则版本和运行 ID。相同输入与相同规则生成相同规范结果；再次加工规范结果不应继续产生新修改。运行时间等审计字段独立于规范产物。

### 汽车参数与隐私处理的保护原则

词语归一不能改变参数。数值、单位、范围、否定词、警告等级、故障码和零件号列为受保护项；变化必须报告并阻断自动通过。首版不自动做物理单位换算。示例“O₂ sensor → 氧传感器”只修改术语，不把原文中的参数改写为推断值。

手机号或车牌识别与部件号存在冲突时，不直接删除。先检查品牌术语白名单、上下文和保护类型，再决定脱敏或人工复核；对外展示的报告也使用脱敏视图，避免审计记录再次暴露原始个人信息。

### 质量状态与输出

| 状态 | 触发情况 | 处理方式 |
| --- | --- | --- |
| 通过 | 所有必检项完成且没有未解决警告或错误 | 允许导出为可入库结果 |
| 待复核 | 未知术语、多义引用或无法确认的提取缺失 | 保留候选结果，禁止标为已通过 |
| 失败 | 解析失败、关键参数变化或结构校验错误 | 隔离结果，保留诊断，不写入正式知识集 |

输出包含规范 Markdown、规范 JSONL、机器可读质量报告与可查看的审阅报告。检索分块保留标题上下文与证据 ID，避免将表格行拆到无法理解的独立片段。

## 五 样例 验收口径与风险

以下数值是建议验收目标，需在实施前冻结测试集和标注口径。结果必须注明样本规模、适用范围与失败案例，不将小样本成绩包装成生产效果。

### 样例集与可验证指标

准备至少 20 份自制文档或记录，覆盖两个虚构品牌、四类输入 PDF DOCX HTML JSON，PDF 中至少两份为扫描样例；含表格、章节引用、中文术语和故意注入的问题。另建开发样例与独立验收样例，避免直接按验收文本编写规则。

| 指标 | 统计方法 | 建议门槛 |
| --- | --- | --- |
| 转换完整性 | 人工标注必保留块，计算成功恢复块数 / 标注块数 | ≥95%；关键参数表不得漏失 |
| 术语归一 | 独立标注集中计算替换 precision 与 recall | 准确率 ≥98%；召回率 ≥90% |
| 保护项不被篡改 | 核对数值、单位、否定词、警告、故障码、部件号 | 验收集零误改；风险项进入复核 |
| 问题检出 | 至少 20 个独立注入缺陷，核对严重等级与定位 | 错误级缺陷全部检出；其余 ≥90% |
| 追溯与配置隔离 | 抽查来源；同名词在两个品牌中交叉运行 | 每条知识可定位；无跨品牌污染 |
| 确定性与幂等性 | 相同输入及配置重复运行，比较规范产物 | 规范产物一致；再次加工无新增修改 |
| 检索效果 | 至少 30 道固定题，记录证据命中 Recall@5 | 整体目标 ≥90%；同时报告分品牌结果 |

转换完整性不等同于输出字数比；术语指标同时报告分子和分母；检索指标按标注证据计算，不把生成回答的流畅程度当作命中。未达门槛时给出原因和修改方案，再决定修复、缩小支持范围或更换底座。

### 主要风险与应对

扫描表格和跨页表格：建立专项样例，发现遗漏时阻断入库并显示原页。HTML 隐藏内容：只承诺已支持策略，遇到外部 CSS 或脚本依赖时提示复核。规则过度替换：保护项检查、白名单和修改差异同时约束。

模型与硬件：首轮验证记录运行设备、模型、时间和内存，下载失败给出可重试状态。许可证与数据：自制样例明确标为演示材料，公开文档建立来源及使用权限记录。现有仓库变更：保持原状，开工前先确认采用子目录还是现有仓库根目录，避免覆盖已有内容。
