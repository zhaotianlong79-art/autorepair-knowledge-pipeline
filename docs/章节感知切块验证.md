# 章节感知切块实现与验证

版本：0.5.0；日期：2026-11-20。对应《知识库建设与实施计划》第 2 项。

## 已实现行为

正式知识库以章节切块作为检索单位。短正文在同一章节及步骤组内组合，长正文按字符偏移拆分；不覆盖原始解析块。每块保存稳定 ID、源块 ID、正文范围、章节路径、步骤 ID、页码、图像资源引用、链接、算法版本和配置摘要。

默认目标长度为 800 字符，上限为 1200 字符，均以 Python 字符数量计，不是模型 token 数。优先在空白和标点附近分割，无合适位置时按字符边界分割。源字符不被丢弃或复制到其他主片段；关联上下文单独返回，允许重复。

| 内容 | 处理规则 |
| --- | --- |
| 章节 | 依据实际标题级别维护路径；同名独立标题保持不同章节 ID；缺少标题时使用已提供的章节元数据 |
| 续页 | 明确的 `(continued)`、`(续)`、`（续）` 且名称与当前章节相同，继续原章节；原续页标题仍保存为源片段 |
| 步骤 | 保留数字／字母标记和嵌套深度；最外层有序步骤开启步骤组，子步骤、后续正文与图表留在组内 |
| 表格 | 保持完整 Markdown 表格；超长时独立成块并标记 `oversized`，保留全部表头和行 |
| 图片及图注 | 作为完整片段，保存图片资源路径；同一步骤及直接相邻的图表说明建立关联 |
| 警告／提示 | 保持完整；支持解析器的 `callout` 及常见中英文警告前缀；章节首个步骤前的提示作为章节上下文，传递给下级章节 |
| 显式引用 | 保留原链接；唯一可解析的文档内锚点建立 `explicit-reference` 关联，不下载外部链接，不猜测歧义锚点 |
| 原文对照 | 原文模式独立切块，重新计算原文偏移；不复用规范化文字的偏移 |

不可拆分的表格、图片、图注、警告，以及超长列表前缀可超过长度上限。每个超长块都有 `oversized=true` 和原始片段，系统不静默截断。长步骤正文仍可以分片；续片保留步骤标记，并关联完整源步骤，便于核对。

## 关联的含义和边界

- `step-context`：同一最外层步骤下的阅读顺序上下文。不同根步骤不因短文本合并到同一块。
- `section-warning`：章节提示及继承的上级章节提示。
- `adjacent-context`：同一章节中与表格、图片或图注直接相邻的内容；不越过下一根步骤附会图表。
- `explicit-reference`：文档内唯一锚点对应的源块。

这些规则保留可核对的上下文，不证明安全警告或参数的业务适用关系。位于两个步骤之间的提示，按源阅读顺序归入前一步；其是否适用于后一步需人工核对。未带明确锚点的远距离图文指代暂不作语义解析。

每个检索结果分别返回主片段 `parts` 与关联源块 `related_blocks`。相关性只计算章节路径和主块文字，关联内容不会重复参与打分、制造额外命中。工作台在“关联警告、步骤及图表上下文”中显示关联内容及依据；完整图片预览和可点击原页定位仍属于第 4 项。

## 存储与使用

SQLite 新增 `knowledge_chunks` 和 `document_chunk_state`，保存当前通过资料的切块及内容／配置摘要。启动时对旧库补建缺失切块，并修复已检测到的配置、文档摘要或块数变化。文档更新、切块替换、状态变化在同一保存事务中处理；待复核及失败会撤下正式切块，历史运行保持原样。

```bash
# 正式知识库以章节块检索，结果包含关联和切块配置
uv run autorepair search '氧传感器' --brand aurora

# 查看当前正式切块，doc-id 可选
uv run autorepair chunks --brand aurora
uv run autorepair chunks --brand aurora --doc-id DOC_ID
```

加工输出和工作台 ZIP 新增 `knowledge-chunks.jsonl`，只包含本次通过的资料。历史 `--run` 查询及“检索对照”继续使用源块，便于维持原有审计口径。配置可通过 Python 的 `ChunkConfig(target_chars=..., max_chars=...)` 传给纯切块函数；正式库当前使用版本化默认配置。

## 验证结果

- 完整测试套件：**87 项通过**；Ruff 检查和格式检查通过。
- 原有 22 个格式样例重新转换回归：271/271 个文字检查点、21/21 个表格网格、19/19 个多级章节通过。
- 切块覆盖审计：**26 份输入、437 个源块，生成 155 个规范化章节块**；30,416 个规范化源字符逐一按偏移还原，无源块或字符缺口、重叠。原文模式单独核对同样通过。
- 26 份输入由 1 份自制关联样例、22 份重新转换的格式样例，以及此前 3 份真实维修通报的本地已核对转换结果组成。真实资料仅复用转换缓存执行切块审计，继续保持 `review`，未被放入正式知识库。
- 自制样例固定覆盖跨页步骤 11/12、嵌套步骤、章节警告、局部警告、超长表格、图片／图注、同名独立章节与长正文。检查切块边界以外仍能返回正确步骤上下文，且不会连接到下一根步骤。
- 入库验收覆盖旧库补建、缓存修复、品牌隔离、重复处理、撤下过期切块、派生索引失败时整笔回滚、CLI 导出及独立界面检索。

统计与限制见 [chunking-results.json](chunking-results.json)。该审计验证的是**已转换内容到切块的覆盖**，不证明原始 PDF/DOCX 无遗漏，也不证明关联规则能理解任意维修语义。

复现本轮格式转换与切块审计：

```bash
uv sync --frozen --extra docling
HF_HOME="$PWD/work/huggingface" HF_HUB_OFFLINE=1 uv run --extra docling pytest -q
FIDELITY_REQUIRE_PASS=1 FIDELITY_OUTPUT="$PWD/work/fidelity-v050" \
  HF_HOME="$PWD/work/huggingface" HF_HUB_OFFLINE=1 \
  uv run --extra docling python scripts/test_markdown_fidelity.py
uv run python scripts/evaluate_chunking.py
# 若本机保留此前真实通报的转换结果，再加：
uv run python scripts/evaluate_chunking.py --real-cache work/real-documents/fixed
```

首次下载模型时不要设置离线变量。真实来源与转换缓存未随仓库分发，默认审计只有 23 份自制输入；加本地真实缓存后为本轮 26 份。
