# 汽车维修知识库建设与实施计划

日期：2026-11-20。文档转换以 0.3.0 为基础，后续按下表顺序实现，每项完成后更新代码、测试和本文件。

## 目标与边界

将已加工资料积累为可持续维护的知识库，支持按品牌、车型、年份查询，并返回可核对的原文、表格、图片和来源。知识库的基本链路为：审核通过 → 章节切块 → 元数据入库 → 索引 → 全库检索 → 证据展示 → 可选问答。

沿用 SQLite、现有品牌 YAML、质量门禁和本地工作台。第一阶段继续使用已有 BM25，无需增加模型或付费 API。待复核文档不进入正式查询；历史运行只供审计及明确选择的演示检索。

## 第 1 项的具体设计

- `documents` 继续保存当前通过的文档内容，新建 `document_catalog` 记录每份文档最近一次处理状态、来源运行、规则摘要和复核记录。
- 同一品牌及 `doc_id` 只保留一个当前状态。不同文件产生不同内容哈希时，默认是不同文档；第 5 项已补充显式逻辑身份及替换，不凭文件名猜测版本关系。
- 默认查询当前全库；显式传入 `--run` 才查询历史批次，保持原有演示对照能力。历史查询结果不代表当前仍获准发布。
- 全库查询只读取正式通过项，返回文档、块、章节、来源位置与批准运行，防止重新处理后的旧证据被继续召回。
- 工作台增加独立“知识库”入口，重启后也可列出并检索已积累文档，不必重新点击“开始加工”。
- BM25 第一阶段按查询从当前文档构建内存索引，尚无持久化向量索引，也不宣称支持大规模语料。
- 旧数据库自动补建目录，不改写历史运行；未知或无法恢复的运行来源明确留空。

验收包括：两批通过文档同时可查；品牌隔离；待复核排除；同 ID 更新与撤下；旧库迁移；来源追踪；CLI 与界面能在未加工新文件时使用正式知识库。

## 数据与发布

公开仓库保存代码、自制样例、测试和方案。真实维修资料及其完整衍生产物继续仅保存在本地。测试不会绕过现有质量门禁，将待复核的厂商通报伪装为正式知识。

## 第 1 项使用方法

```bash
# 正式知识库的最新目录与跨批次查询
uv run autorepair catalog --brand aurora
uv run autorepair catalog --brand aurora --status passed
uv run autorepair search '氧传感器' --brand aurora

# 显式历史审计，可选包含候选材料；请填写实际运行 ID
uv run autorepair search '氧传感器' --brand aurora --run RUN_ID --include-review
```

默认数据库为 `artifacts/knowledge.sqlite`，命令可用 `--database` 指定其他库。界面选择「知识库」后可筛选目录状态并输入关键词；普通检索无匹配时提示无证据；问答需显式点击或使用 `ask`。车型、年份等字段支持录入、过滤及修正留痕；未录入时保持 `unknown`。0.9.0 另提供可选本地语义和混合检索。
