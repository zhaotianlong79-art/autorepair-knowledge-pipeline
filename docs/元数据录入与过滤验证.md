# 元数据录入、适用范围过滤与修正留痕

版本：0.6.0；日期：2026-11-20。对应知识库建设计划第 3 项。

## 已实现

工作台上传和命令行支持车型、年份、资料类型及资料版本录入。批次默认值可被单文件清单覆盖；不填写时保留文件已有信息。未知值保持未知，不根据文件名、发布日期或正文猜测车辆适用范围。

| 字段 | 数据及规则 |
| --- | --- |
| `model` | 单车型显示值；去除首尾及重复空白，车型匹配忽略大小写，不作模糊别名推断 |
| `year_range` | 单年 `2024`、连续区间 `2020-2022`，或录入值 `unknown`；端点范围限定为 1900–2200，拒绝逆序、两位年份及残缺范围 |
| `document_type` | `unknown`、`manual`、`service_bulletin`、`procedure`、`wiring_diagram`、`parts_catalog`、`training`、`other` |
| `document_version` | 显式资料版本标签，如 `v1`；筛选按空白规范化后的精确值匹配，区分大小写，不自动选择“最新版本” |
| `applicability` | 多车型／不连续年份使用配对数组，每项包含 `model`、`year_start`、`year_end`；年份端点须同时提供或同时未知 |

多车型数组是适用关系的依据，顶层车型和年份用于显示。不会将 A 车型的年份与 B 车型组合；不连续年份应填写多条范围。空数组 `[]` 表示清空适用范围为未知。单车型／年份字段与完整数组不能同时提交，多车型文档须通过完整数组修正。

## 录入示例

```bash
uv run autorepair process examples/dev/aurora/01-manual.html --brand aurora \
  --model 'Demo Sedan' --year-range 2020-2022 \
  --document-type manual --document-version demo-v1

# 清单中的路径相对于清单文件；逐文件覆盖批次默认值
HF_HOME="$PWD/work/huggingface" uv run --extra docling autorepair process examples/dev/aurora \
  --brand aurora --metadata-manifest examples/metadata/demo-manifest.json
```

[演示清单](../examples/metadata/demo-manifest.json) 使用自制品牌与示例适用值。清单只能引用当前加工批次里的文件，拼错或重复路径、未知字段、非法范围会被拒绝。命令行也支持 `--applicability '[{"model":"Demo Sedan","year_start":2020,"year_end":2021},{"model":"Demo SUV","year_start":2024,"year_end":2025}]'`。

工作台在“车型、年份和资料信息”中录入批次默认值；上传后可在单文件表格中分别填写。空白字段表示不覆盖；明确重置可填写 `unknown` 或完整空数组。

## 过滤规则

品牌始终由知识库范围限定。车型、年份、类型、版本各条件之间使用 AND；同一文档的多条适用关系之间使用 OR，但车型和年份必须在**同一条关系**中匹配。过滤在 BM25 排序前执行，目录和历史批次查询使用相同匹配规则。

- 单年查询要求位于端点之间，含边界；年份区间查询采用**区间相交**，不表示文档覆盖查询区间的全部年份。
- 指定某字段时，默认排除该字段未知的资料。未指定的字段不限制；不强制排除所有带未知信息的文档。
- `--include-unknown` 只允许过滤字段未知的候选进入；已知不匹配的车型、年份、类型、版本仍被排除。
- 包含未知字段的结果返回 `metadata_match.uses_unknown=true`，工作台显示“不能确认适用于所选车辆”。这不代表确定适用。
- `unknown` 可用于录入未知年份，不能用作年份查询来静默关闭筛选。旧库无法解析的年份只按未知处理，绝不当作全年份。

```bash
uv run autorepair search '氧传感器' --brand aurora --model 'Demo Sedan' --year 2021 \
  --document-type manual --document-version demo-v1
uv run autorepair catalog --brand aurora --model 'Demo SUV' --year-range 2024-2025
# 若需要检查适用信息缺失的资料，显式增加：
uv run autorepair search '氧传感器' --brand aurora --year 2021 --include-unknown
```

历史查询 `--run RUN_ID` 筛选的是当时保存的元数据，不套用后来的修正，也不代表文档目前仍通过门禁。

## 修正留痕与一致性

工作台“元数据修正与历史”及 `metadata-correct` 支持逐文档编辑，必须填写操作人和原因，并基于当前 `metadata_revision` 提交。修订号冲突时拒绝覆盖，用户须刷新。

```bash
# 先查看文档 ID 和 metadata_revision
uv run autorepair catalog --brand aurora
# 使用实际文档 ID 及当前修订号
uv run autorepair metadata-correct --brand aurora --doc-id DOC_ID --expected-revision 1 \
  --document-version demo-v2 --actor '本地维护人' --reason '核对修订页后更新'
uv run autorepair metadata-history --brand aurora --doc-id DOC_ID
```

每次实际变化保存前后完整元数据快照、时间、录入／人工修正来源、操作人、原因、旧运行和新运行。原文、来源哈希、正文块及历史运行不被覆盖。录入时记录 `local-ingest`，人工操作人是本地填写的署名，不等同于登录身份认证。

修正创建新的审计运行，保留通过／待复核／失败状态与原有问题，不能解除质量门禁。当前目录、文档和派生切块在同一事务中更新；任何派生索引写入失败都会回滚修改及审计记录。

同一文档重新加工时，不提供新元数据会保留原修正；只提供部分字段时以原元数据为基础覆盖这些字段。显式完整规范 JSON 中的元数据仍可作为新输入。内容变化产生新文档 ID 时不会自动继承旧文档的适用范围，版本替换机制仍属于第 5 项。

导出和 ZIP 新增 `metadata-history.json`；历史导出文件不被反向覆盖。CLI 修正后的当前状态与记录保存在 SQLite，通过 `metadata-history` 可取出。旧数据库自动补齐目录列，缺失类型及版本仍为 `unknown`，不伪造旧操作人的修改记录。

## 验证结果

- 完整套件 **119 项通过**；其中新增 32 项参数化验收，覆盖年份边界／非法输入、多车型配对、未知策略、品牌与审核隔离、旧库迁移、清单覆盖、修正并发与回滚、重新加工保留修正，以及 CLI 和工作台实际操作。
- 原有 22 个格式样例回归通过：271/271 个文字检查点、21/21 个表格网格、19/19 个多级章节通过。
- 切块覆盖审计继续通过：26 份输入、437 个源块、155 个规范化章节块。真实资料仅复用本地转换缓存，保持待复核。
- 浏览器验证：未知车型资料默认不匹配指定车型；显式包含后出现适用性未确认提示。演示清单实际加工及 `Demo Sedan / 2021 / manual` 组合查询返回一份符合条件的资料。

本轮不实现车型别名库、VIN／市场／发动机／配置适用关系推理，也不自动识别或比较厂商版本号；这些字段缺失时，检索匹配不能代替对原文适用条件的核对。
