# 真实汽车维修文档转换验证

测试日期：2026-11-20；修复版本：0.3.0。

本轮选择 3 份厂商维修通报，共 16 页。对原始 PDF 全部页面渲染检查，并固定页码、表头、行列关系、章节级别、图片区域和步骤编号作为核对依据。修复前后的检查定义一致，结果文件可对照查看。

## 实际修复

1. **稀疏边框表格退化。** Toyota 一张三列表格只有少量边框，矢量检测将其看作一列。现在低列数的边框结果不能覆盖更完整的布局解析结果。
2. **多行表头和车型分组。** 将实际观察到的父子表头展开成一行 Markdown 表头，保留父级名称；整行合并的车型标题移到表格前。按真实单元格几何展开共享值，原始空白仍为空白。
3. **未编号章节和误判页眉。** 优先读取 PDF 的 Hn 标签，补回被布局模型放入页眉区的章节；无语义标签时依据字体、字号和重复样式推断层级并标注 `structure.inferred`。原生章节标签优先于重复页眉规则。日期和版本信息保留为正文。
4. **步骤标记被重置。** 保留原始数字、字母标记；普通圆点规范为 Markdown 项目符号，避免所有步骤显示为 `1.`。
5. **小图标遗漏。** 按原始 PDF 图像位置补充未被图片块覆盖的区域，保留页码与包围框，避免重复提取。Honda 警告图标已补回。小于面积阈值的装饰图片仍可能被跳过。
6. **OCR 提示误报。** 未请求图片 OCR 时，不再报告“图片文字未识别”；原图复核提示保留。

## 验证与限制

- 原有 22 个自制格式样例复测：271/271 个内容检查点、21/21 个表格网格、19/19 个多级章节通过，覆盖 HTML、HTM、JSON、DOCX、数字 PDF 和扫描 PDF。
- 完整测试套件：51 项通过；Ruff 检查及格式检查通过。
- 新增合并表头、稀疏边框、原生章节优先级、扫描页无字体信息、步骤标记和小图标回归测试。
- 3 份真实文档均保持 `review` 状态，未自动进入通过语料。字体推断的层级需要人工确认，安全提示、参数与跨页关联仍应对照原文。
- 本轮是短篇数字版维修通报的抽样验证，没有证明整本维修手册、所有扫描件或任意复杂表格无损转换；Markdown 也不保留原 PDF 合并单元格的视觉布局。

## 复现

```bash
uv sync --extra docling
# 首次运行需要下载 Docling 模型；已有缓存可设置 HF_HOME。
uv run python scripts/test_real_documents.py --download --stage fixed
uv run python scripts/audit_real_checks.py --stage fixed
```

完整本地产物位于 `work/real-documents/fixed/<厂商>/`：`output.md`、`output.html`、`result.json` 和 `assets/`。下载文件哈希改变时脚本直接失败，避免静默替换测试源。修复前结果来自 0.2.0（`e3703965c5c8139093a828f53396a5865d97b863`），当前版本运行 `--stage before` 不会还原旧代码。
