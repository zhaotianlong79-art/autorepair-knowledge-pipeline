# 本地语义与混合检索实现与验证

版本：0.9.0；日期：2026-11-20。对应建设计划第 6 项。

## 实现范围与选择

已提供 `bm25`、`semantic`、`hybrid` 三种正式检索方式，命令行与工作台均可选择。默认继续使用 BM25；没有模型依赖时，原有转换和关键词查询仍能工作。第 7 项带引用问答尚未实现。

选用 `BAAI/bge-small-zh-v1.5` 作为首个本地中文模型，固定修订 `7999e1d3359715c523056ef9478215996d62a620`。采用 CLS 池化、L2 归一化及中文查询指令，512 维向量；默认 CPU。配置包含模型仓库、修订、维数、查询前缀、窗口及算法版本，整体摘要隔离不同向量空间。`Embedder` 协议及 `EmbeddingConfig` 支持通过 Python API 注入其他本地实现；内置加载器实现 CLS，不自动适配其他池化策略。

依据：[BGE 官方模型说明](https://huggingface.co/BAAI/bge-small-zh-v1.5)、[Transformers 模型加载文档](https://huggingface.co/docs/transformers/main_classes/model)。模型许可证为 MIT；模型权重不进入本仓库。选择小模型先验证本机资源和中文召回，没有声称它是汽车维修领域最优模型。

首次准备模型需显式下载。普通查询仅加载本地固定修订缓存，`trust_remote_code=False`，仅加载 safetensors；文档正文及问题不发送给远程推理服务。缺少依赖、模型或配置不一致时明确报错，不静默切换为 BM25。

## 检索和证据

- 品牌、车型、年份、资料类型、版本及未知值策略先过滤，再生成候选向量。仅允许当前活动且通过质量门禁的资料。
- 语义模式：对章节路径与所属正文计算相似度，按最大窗口余弦分数排名。关联图表和警告继续展示，不额外拼接进入排名来放大分数。
- 混合模式：BM25 和语义各取排名候选池，使用等权 RRF：`1/(60+关键词排名) + 1/(60+语义排名)`。候选池至少 50 条；不直接相加不同尺度的分数。
- 返回来源运行、规则摘要、切块版本、原始块、页码、表格、关联图片及步骤。语义结果另带模型配置、余弦分数和最佳窗口偏移；混合结果记录实际参与的分支排名及分数。
- 常见故障码及带连字符部件号使用完整标识匹配，避免 `P0300` 被 `P0301`、`90919-01253` 被邻近部件号替代。此保护作用于语义／混合模式，且不是覆盖全部厂商编号的通用解析器。
- 当前语义模式仅查询规范正文。原文对照和显式历史运行继续使用 BM25，避免候选和旧版本混入正式向量查询。

超长表格、正文及警告按 256 字符、48 字符重叠形成嵌入窗口，尾部必须覆盖；模型编码前检查实际 token 数，超限报错，不静默截断。向量窗口不改变原来的章节切块或展示内容；查询最多 400 字符。最佳窗口偏移基于“章节路径 + 换行 + 正文”，不是 PDF 坐标。

## 持久化与生命周期

向量存放在同一个 SQLite 的 `semantic_vectors` 派生缓存表，按品牌／文档／切块／配置摘要唯一绑定，并检查正文摘要、配置、窗口偏移、维数、归一化及缓存内容摘要。

- 查询按当前已过滤切块按需补齐向量；重复查询复用正文向量，问题向量每次重新编码。
- `semantic-index --mode check` 检查差异和过期缓存，不加载模型、不重写向量或维护审计；CLI 检查关闭启动自动修复。首次旧库初始化仍可能建表迁移。
- `incremental` 仅补齐缺失／损坏／变化项，`rebuild` 重编码该品牌全部活动切块；维护要求署名和原因，并写生命周期审计。计算或写入失败时整个维护事务回滚。
- 旧版本撤下、替换或审核失效后，其向量立即失去查询资格。残留缓存可保留到显式维护时清除，不能作为发布依据。维护同时清理该品牌非活动切块和其他配置的缓存，不影响其他品牌。
- 第 5 项 `index` 维护正文与章节切块；`semantic-index` 维护向量，两者职责和配置分开。索引维护不修改原件保留策略，也不清理历史正文及图片。

当前是在 SQLite 中持久化向量、在内存线性计算相似度，没有采用近似最近邻数据库。查询和维护按本地单用户设计，首次补齐大量向量会耗时并持有写事务；不能据此宣称支持大规模或高并发语料。缓存摘要用于一致性检查，不对能修改整个数据库的攻击者提供防篡改认证。

## 使用方法

在项目根目录执行；以下直接调用同步后的虚拟环境，避免运行时重选可选依赖。

```bash
uv sync --extra docling --extra semantic

# 如需与本项目已有模型使用同一缓存，先设置；后续启动应用也保持一致
export HF_HOME="$PWD/work/huggingface"
.venv/bin/autorepair semantic-model                 # 只查看配置
.venv/bin/autorepair semantic-model --download      # 显式准备固定修订模型

.venv/bin/autorepair semantic-index --brand aurora --mode check
.venv/bin/autorepair semantic-index --brand aurora --mode incremental \
  --actor '维护人' --reason '为当前正式资料补齐向量'
.venv/bin/autorepair semantic-index --brand aurora --mode rebuild \
  --actor '维护人' --reason '重新生成当前品牌向量'

.venv/bin/autorepair search '刹车踩着发软怎么检查' --brand aurora --mode semantic
.venv/bin/autorepair search 'P0300 检查项目' --brand aurora --mode hybrid \
  --model sedan --year 2024
```

默认数据库是 `artifacts/knowledge.sqlite`，各检索和索引命令可用 `--database PATH`。模型首次准备需要网络；准备后可设置 `HF_HUB_OFFLINE=1` 检查离线运行。若首次准备时已有该环境变量，应先解除离线限制。

工作台「知识库」新增「检索方式」和「本地语义模型与索引」。模型缺失时显示操作说明；模式切换不改变审核状态、适用范围或来源证据。

## 真实模型对比

公开自制资料见 [固定语料与问句](../examples/retrieval/corpus.json)，结果见 [逐题结果及资源记录](retrieval-results.json)。由脚本通过真实 HTML 解析、规则加工、审核门禁、存储及正式查询执行；没有用模拟向量代替质量评估。

共 13 类资料，每类 2 道题，在两个虚构品牌分别运行：**26 道不同问句、52 次检索评估**。两个品牌的资料正文相同，因此这不是 52 个独立语义样本。另有 4 道无答案问题在两个品牌执行，共 8 次观察。所有评估资料为自制示例，不是可直接指导维修的厂商资料。

命中要求前三条中同时包含正确来源文件和标注的正文证据；仅命中手册标题不计。使用固定题集，无盲测、无参数搜索，未用此结果证明真实手册泛化效果。

| 模式 | 首条命中 | 前三条命中 | MRR@3 | 查询中位数 | P95 |
| --- | --- | --- | --- | --- | --- |
| BM25 | 32/52 | 42/52 | 0.7051 | 1.078 ms | 1.297 ms |
| 本地语义 | 42/52 | 52/52 | 0.9038 | 8.114 ms | 8.826 ms |
| 等权混合 RRF | 35/52 | 46/52 | 0.7788 | 8.253 ms | 8.879 ms |

以上是本机、已加载模型且正文向量缓存完成后的查询耗时，包含 SQLite 读取、过滤及问题编码；不包含首次权重下载。不要推算为大型语料的延迟承诺。语义在本题集优于混合，RRF 的关键词分支可能把泛词匹配排在正确语义候选之前，因此不把混合作为强制默认。

资源实测：模型约 2395 万参数、参数张量 95,815,680 字节；本次进程模型加载约 1.74 秒。两个品牌共 26 份文档、52 个切块，向量 JSON 载荷 561,896 字节，不包含数据库其他表与索引。含 3430 字符长表格的 17 个窗口编码验收后，整个评估进程峰值 RSS 约 612 MiB；包含 Python、模型、分词器和评估开销，不等于模型单独占用。

另实测确认：长表格尾部覆盖且全部窗口向量有效；品牌与适用范围过滤有效；无答案故障码及部件号在语义／混合模式下无结果。普通无答案问题（如电饭锅维修、二手车未来价格）仍返回语义候选，**不能将相似度或 RRF 分数视为答案存在的证明**。界面明确提示候选需核对，不生成回答；问答的拒答与引用校验属于第 7 项。
